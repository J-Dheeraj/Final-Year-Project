AI CVE Exploit Automation

Pipeline architecture

An 8-stage pipeline that fetches a real CVE advisory, classifies the bug, generates an exploit and a faithful vulnerable target with a local or hosted LLM, actually runs it as a real subprocess, self-improves on genuine failure, and validates a generated patch against multiple attack payloads — for both Python and JavaScript targets.

One provider-agnostic call site backs all three LLM-touched stages — Claude CLI first, a local Ollama model as fallback, with real duration/token/cost recorded on every call, not estimated. The interpreter branch is the one line that lets Stage 3.6 run a JavaScript target: everything else in the pipeline is unaware the target isn't Python.

Stage reference

StageDoesEvidence type
1 Fetch the real advisory from NVD v2 / GitHub Security Advisories. real API
2 Classify the vulnerability into one of 7 classes from the advisory text + CWE. heuristic
3 Live probe — real for SSRF and memory-safety; static pattern match for the rest. mixed
3.5 Generate a minimal vulnerable target + PoC exploit for this specific CVE. LLM-generated
3.6 Actually start the target, poll /health, run the PoC, read the real exit code. real subprocess
3.7 On genuine failure: reuse a persisted lesson, or ask the LLM to diagnose and rewrite. LLM-diagnosed
3.8 Generate a patch, then require it to survive the original payload and every alternate payload. re-validated
4 Compile the full report — curl commands, bypass results, real cost/token totals. structured JSON
